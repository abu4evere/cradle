## Agreed (taken)
- **A reward per lid stays** (all three): a full-box-only reward floors near 0.
- **3 lids is enough** (all three). Watch for a floor on full-box success; the per-lid score is secondary.
- **Demonstrations must stop at the demonstrator's first wrong lid** (GPT, Gemini): someone who fails lid 1 cannot
  show lid 2.
- **The copy step must not leak later lids** (Gemini, DeepSeek): copying all 3 demonstrated pairs lets the child learn
  lids it never reaches, which bypasses the cumulative bottleneck. Taken: in the cumulative condition, the child copies
  lid j only if it reached lid j in its own try that day.
- **Separate the chain from plain harm** (Gemini, "sabotage rather than gating"): choosing could win only because bad
  copies overwrite the weights. Taken: every arm also runs on **flat** boxes, where a wrong lid does not end the try and
  every demonstrated lid is copied. The interaction (choosing's gain, cumulative minus flat) isolates the chain.
- **The amount of copying** (GPT): an oracle-volume control, Cr, copies with a fair coin, w = 1 or 0.

## Points from one model
- **GPT:** the network needs memory for the 3 pairs.
  - **Corrected:** the input carries the demonstrated pair for the current lid at each lid (a separate channel), so no
    memory is needed.
  - GPT also proposed a novel-box transfer test. The novel boxes are reported as in C2.
- **DeepSeek:**
  - per-lid outcome feedback for trust. Taken: Ctk's trust updates from the share of lids the demonstrator opened (when
    the result is seen);
  - the oracle is handed the expert mapping, so it is an upper bound by design. As labelled;
  - one-sided tests and a floor guard. Taken: if Cb's cumulative full-box success at day 30 is under 0.05, readings 1–3
    are "not readable".
